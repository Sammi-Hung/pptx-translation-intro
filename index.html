公司內部教育訓練工具

從語言理解落差，到 PowerPoint 多語言教材轉換工具

這份簡報不是只介紹功能，而是說明需求如何從一個實際問題開始，一路收斂成目前可操作的網站。

如何讓不同語言背景的員工，都能比較完整地理解同一份教育訓練簡報內容？
使用方向鍵或空白鍵換頁，點擊圖片可放大
背景需求

起點不是「翻譯工具」，而是教育訓練的理解落差

公司現場遇到的問題

外籍員工可能不熟悉中文，也不一定能完全理解英文。當教材只有單一語言時，訓練內容容易被片段理解。

簡報內容不只在畫面上

講師真正要補充的說明，常常寫在 PowerPoint 講者備註裡。因此只翻譯投影片文字，仍然不夠完整。

專案逐漸從「簡報文字翻譯」變成「投影片內容加講者旁白的多語言轉換」。
初始想法

最初希望使用者只需要完成三件事

1

上傳簡報

只接受 .pptx，一次處理一份檔案。

2

選擇語言

支援繁體中文、英文與泰文。

3

下載結果

系統完成翻譯與語音嵌入後，直接下載新簡報。

首頁畫面：左側上傳簡報，右側選擇語言、模型與檢查 Windows 語音包。

操作流程收斂

等待處理時，使用者需要知道系統正在做什麼

驗證上傳檔案
解析簡報內容
翻譯投影片文字
翻譯備註並產生語音
嵌入音訊並輸出

避免重複送出

翻譯開始後會鎖定上傳區、語言選單與模型選單，避免同一時間處理多個檔案造成狀態混亂。

進度來自後端狀態

畫面每秒查詢後端工作狀態，顯示目前階段、處理頁數、總頁數與即時訊息。

最重要的一次需求收斂

PowerPoint 裡不是所有東西都適合第一版翻譯

第一版處理範圍

  • 一般文字方塊
  • 標題 Placeholder
  • 本文 Placeholder
  • 內容 Placeholder 中的文字
  • 每張投影片的講者備註正文

第一版刻意不處理

  • 圖片內文字、表格、SmartArt 與圖表
  • WordArt、群組物件與嵌入式物件
  • 音訊、影片、頁碼、日期與頁尾

這個收斂讓系統更穩定，也降低翻譯過程破壞原始簡報排版的機率。

格式保留

翻譯不能只是把整個文字方塊覆蓋掉

段落單位

以段落為主要翻譯單位，盡量保留原本段落順序與條列層級。

保留樣式

保留文字方塊位置、大小、字型、字體大小、粗斜體、顏色與對齊方式。

避免溢出

翻譯後若文字可能超出文字框，逐步縮小字體，仍有風險時顯示警告。

目的不是做一份全新簡報，而是在盡量不破壞原始版面的前提下完成多語言轉換。
關鍵特色

講者備註讓工具不只是「翻譯投影片」

投影片文字路徑

原文投影片文字 → 翻譯 → 寫回原本位置。

講者備註路徑

原始備註 → 翻譯 → 寫回備註 → Windows SAPI 產生語音 → 嵌入對應投影片。

語音功能的第一版邊界

只使用投影片原本的講者備註產生旁白。沒有備註的頁面不自動產生講稿，也不拿投影片文字代替。

技術限制與決策

開發過程中的限制，也反過來定義產品邊界

翻譯模型切換

保留雲端模型與地端 Ollama 模型切換介面，讓公司可依成本、速度與資料安全需求調整。

Windows 本機語音

第一版採用 Windows SAPI，不額外產生外部語音費用，但語音品質與可用語言取決於電腦安裝的語音包。

最終成果

最後形成一個可操作、可驗證、可下載的網站流程

處理中畫面會顯示目前階段、進度百分比、頁數與可即時停止的按鈕。

完成後顯示輸出檔名、總頁數、語音頁數、警告數與下載按鈕。

最終定位

這是一套降低多語言教材製作門檻的內部工具

帶來的價值

  • 降低不同語言背景員工的訓練理解落差
  • 減少人工翻譯簡報與重錄旁白的時間
  • 讓教材文字、備註與旁白維持在同一份檔案中

第一版保持克制

  • 不加入登入、資料庫與多檔案排隊
  • 不處理 PDF、OCR 或圖片內文字
  • 複雜格式仍保留人工確認空間
從實際教育訓練需求出發，讓同一份 PowerPoint 能更接近多語言可理解、可聽、可下載的教材。
